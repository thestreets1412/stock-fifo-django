<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Cloudflare edge | Untrusted client input arrives; TLS terminates at the edge, which sets `X-Forwarded-Proto: https`. |
| Cloudflare edge → cloudflared → loopback → WSGI/Gunicorn | The forwarded request reaches Django. Django trusts `X-Forwarded-Proto` here — this is only safe because (from Phase 2) Gunicorn binds `127.0.0.1` and nothing but cloudflared can reach it. In Phase 1 the trust is configured; the enforcing binding lands in Phase 2. |
| Browser ↔ Django session/CSRF cookies | Cookies cross the wire; must carry the Secure flag and be protected by HSTS so they never travel over plaintext. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing/Tampering | `SECURE_PROXY_SSL_HEADER` (forged `X-Forwarded-Proto`) | high | mitigate | Header trust is set in Phase 1; documented invariant + `must_haves.prohibitions[0]` requires the Gunicorn process to be loopback-only (enforced Phase 2) so the header cannot be forged by a LAN client. |
| T-01-02 | Information Disclosure | `DEBUG` leaking tracebacks/settings/SQL in production | high | mitigate | `DEBUG = config('DEBUG', default=False, cast=bool)` — fail-closed default; proven by the DEBUG-unset assertion and the `check --deploy` test (Task 3). |
| T-01-03 | Information Disclosure/Tampering | Session/CSRF cookies over plaintext → session hijack | high | mitigate | `SESSION_COOKIE_SECURE`/`CSRF_COOKIE_SECURE = not DEBUG` + HSTS (`SECURE_HSTS_SECONDS`/include-subdomains/preload); verified by `check --deploy` returning zero warnings. |
| T-01-04 | Spoofing (CSRF) | `CSRF_TRUSTED_ORIGINS` placeholder trusts a domain the owner does not control | high | mitigate | Replace the hardcoded placeholder with an env-driven read defaulting to empty (fail-closed); real `https://` origin supplied in Phase 5. Task 1 + source-assertion test. |
| T-01-05 | Denial of Service (self-inflicted) | Missing `SECURE_PROXY_SSL_HEADER` with SSL redirect on → infinite redirect loop, site unreachable | high | mitigate | Proxy header set BEFORE enabling `SECURE_SSL_REDIRECT`; the middleware test proves a forwarded-https request is not redirected. |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | Phase 1 introduces NO new packages (pure settings + a test module using stdlib/Django only). No package-legitimacy checkpoint required; supply-chain surface unchanged this phase. |

ASVS level 1; block on `high`. Every high-severity threat above has a `mitigate` disposition with a concrete implementation and a mechanical or source verification in Tasks 1 and 3.
